# `client/src/views/Auth/OAuthCallback.vue` treats a refreshed, completed OAuth callback as missing authentication data

## Verdict
defect — the callback route deliberately removes its one-time code from the URL, then rejects an authenticated user who refreshes that scrubbed URL.

## What happened
After Google OAuth succeeds, the backend redirects to `/auth/callback` with a one-time `auth_code`; the client exchanges it for JWTs and persists them in `localStorage` through `authStore.setToken` (`client/src/views/Auth/OAuthCallback.vue:77-84`, `client/src/stores/auth.ts:47-61`). The callback immediately removes the query string from the address bar (`OAuthCallback.vue:47-48`). Refreshing then remounts the same route without `auth_code`, causing it to display “Missing authentication data” at `OAuthCallback.vue:73-75`, even though the persisted token means the user is logged in.

## Root cause
The defect was in `client/src/views/Auth/OAuthCallback.vue:69-75`:

```ts
if (!authSuccess) {
    throw new Error(authMessage || "Authentication failed");
}

if (!authCode) {
    throw new Error("Missing authentication data");
}
```

This assumes every mount of `/auth/callback` must carry the original one-time code. That assumption does not hold after the component itself has scrubbed the successful callback URL while the JWT is persisted in the auth store.

## How to reproduce
1. Complete a Google sign-in so the backend redirects to `/auth/callback?auth_success=true&auth_code=...` (`apps/accounts/views.py:137-146`).
2. Allow the client to redeem the code and persist the returned access and refresh tokens (`client/src/views/Auth/OAuthCallback.vue:77-84`).
3. Refresh the now-scrubbed `/auth/callback` URL.
4. Before this fix, the component throws “Missing authentication data”; navigating away or reloading subsequently shows the user as logged in from `localStorage`.

## Blast radius
This affects every user who refreshes or revisits the cleaned OAuth callback route after a successful Google sign-in. The router maps `/auth/callback` only to this component (`client/src/router/index.ts:22-25`); no other client callback route makes this exact validation.

## Applied fix
- `client/src/views/Auth/OAuthCallback.vue:50-56` now checks whether `authStore.isAuthenticated` is already true and the scrubbed query has no `auth_code`; it redirects to home and returns before callback validation. A fresh callback without a token still follows the existing error handling.
- `tests/test_oauth_callback_client.py:15-20` added a regression assertion that the authenticated, no-code early return remains before the callback validation path.

Verify by completing Google OAuth, waiting for the redirect to home, returning to `/auth/callback`, and refreshing it: the application should redirect home without displaying the missing-authentication error. A direct unauthenticated request to `/auth/callback` should still display the existing failure state.
