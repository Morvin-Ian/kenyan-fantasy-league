# The Google OAuth fix landed with no regression test — `tests/test_google_oauth_env.py` (new) now guards the trimmed-credentials contract in `apps/accounts/services.py` so the raw-`os.getenv()` regression that broke every Google sign-in cannot silently return.

## What happened

`apps/accounts/services.py` re-read `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` with bare `os.getenv()` (lines 42–43, 68) instead of the whitespace-trimmed values already computed in `config/settings/base.py:405-406`. Because docker-compose's `env_file:` passes values verbatim, a single trailing space or newline artifact on either line in `.env`/`.env.prod` corrupted the `client_id` sent to Google's token endpoint **and** the `aud` comparison in ID-token validation — so every "Continue with Google" sign-in failed with `Failed to exchange authorization code` or `Token audience mismatch`.

The service code was already fixed (PR #72, `28795e1`, incident `b63a7039aeb50622`): `services.py:9` now does `from config.settings import base`, `services.py:43-44` sends `base.GOOGLE_CLIENT_ID`/`base.GOOGLE_CLIENT_SECRET`, and `services.py:69` compares `token_info.get("aud") != base.GOOGLE_CLIENT_ID`. `grep GOOGLE_CLIENT config/` matches only the two `env()`-hardened definitions in `base.py`; no raw `os.getenv("GOOGLE_…")` read remains anywhere, and `apps/accounts/views.py:38` also goes through `settings.GOOGLE_CLIENT_ID`.

## Root cause of the gap being fixed now

Every sibling incident in this repo ships a regression test — `tests/test_entrypoint.py` (quoted heredoc), `tests/test_allowed_hosts.py` (production host pinning), `tests/test_fantasy_user_team.py` (empty-list contract) — but the Google OAuth env-var incident had **none**. The documented "Applied fix" for `b63a7039aeb50622` lists only the `services.py` edit and a by-hand grep as verification. Nothing in CI would notice if someone reverted `services.py` to `os.getenv("GOOGLE_CLIENT_ID")` tomorrow and silently re-opened the whitespace-corruption path.

## Applied fix

Changed exactly one file, **`tests/test_google_oauth_env.py`** (new, 77 lines), following the repo's source-assertion convention from `tests/test_entrypoint.py`/`tests/test_allowed_hosts.py`:

- `test_services_imports_the_hardened_settings_module` — `from config.settings import base` must be present.
- `test_token_exchange_sends_the_trimmed_client_id_and_secret` — the POST body must use `base.GOOGLE_CLIENT_ID` / `base.GOOGLE_CLIENT_SECRET`.
- `test_audience_check_uses_the_trimmed_client_id` — `validate_token` must compare against `base.GOOGLE_CLIENT_ID`.
- `test_no_raw_os_getenv_reads_of_google_credentials_remain` — neither raw read may exist in `services.py`.
- `test_settings_define_the_credentials_through_the_trimming_helper` — `base.py` must define both via `env()`, not `os.getenv`.
- `test_env_helper_strips_stray_whitespace` — behavioral check that `env()` trims surrounding whitespace, the exact property the incident turns on.
- `test_env_helper_leaves_non_string_values_alone` — `env()` returns the default for unset vars without crashing.

Every source-assertion test fails on the pre-fix `services.py` (which had `os.getenv("GOOGLE_CLIENT_ID")`) and passes on the current tree. The behavioral tests need no Django app state (pytest.ini already points `DJANGO_SETTINGS_MODULE` at `config.settings.development`, and `tests/test_allowed_hosts.py` already imports settings modules at module scope). Run with `pytest tests/test_google_oauth_env.py`.

## What has to be set outside the repository

`GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are runtime secrets and must be provided in the environment (docker-compose `env_file: .env` / `.env.prod`). The repository cannot contain them; what the repo *can* and now *does* control is that both are read exclusively through `config.settings.base.env()`'s trimming path, with a test pinning that contract. The test suite will fail loudly the moment a raw `os.getenv` read is reintroduced.
