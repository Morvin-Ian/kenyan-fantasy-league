# apps/kpl/tasks/fixtures.py: `extract_fixtures_data` assumes the fixtures page always renders `table.sp-event-blocks` and that `TEAM_FIXTURES_URL` is always set — a 200 page without the table fails with nothing actionable

## Verdict
defect — the guard fires on a 200 response that is this app's data source and discards the page content that would diagnose it, while the sibling scrapers in the same package already validate the env var and log the HTML on failure.

## What happened
The every-two-days celery beat task `update-kpl-fixtures` (`config/settings/base.py:379-382`) fetched the fixtures page, received HTTP 200, found no `<table class="sp-event-blocks">`, logged a bare ERROR line, and returned `False`. No fixtures were written, and the beat scheduler records that `False` as a completed task, so the fixture table — and everything downstream of it — stalls without any alert.

## Root cause
`apps/kpl/tasks/fixtures.py:280-297`. The failing assumption is that the page at `TEAM_FIXTURES_URL` always contains a SportPress `<table class="sp-event-blocks">` whose rows are `td > a[3]` (date, time, match):

```python
url = os.getenv("TEAM_FIXTURES_URL")            # :280 — no `if not url` guard
...
web_content = requests.get(url, headers=headers, verify=False)  # :286 — no timeout
...
table = soup.find("table", class_="sp-event-blocks")  # :293 — single hard-coded selector
if not table:
    logger.error("No fixtures table found on the page.")  # :295
    return False
```

When the source page's markup drifts (or the site returns a 200 shell page — bot wall, empty off-season page), the whole extraction aborts on that one class name, and `web_content.text` — the only evidence of what the page actually contains — is thrown away. The row-level checks below (`len(links) < 3`, date parsing) never run, so the scraper cannot distinguish "structure changed" from "no fixtures scheduled". Two further inconsistencies with the sibling scrapers: `url` is read without the `if not url` check that `standings.py:21-24`, `standings.py:244-247`, and `players.py:77-79` all have (an unset variable would surface here as a swallowed `MissingSchema` from `requests.get(None)`), and the request has no `timeout` (compare `standings.py:250`). The sibling `extract_table_standings_data` already handles this exact failure class with three fallback strategies and an `HTML preview (first 1000 chars)` log line (`standings.py:59-97, 232-235`); `extract_fixtures_data` has neither.

## How to reproduce
The specific page is external — `TEAM_FIXTURES_URL` lives only in the server's gitignored `.env.prod` and the live markup of kenyafootballdata.com cannot be fetched from this repo. The code path itself: set `TEAM_FIXTURES_URL` to any URL that returns HTTP 200 without `<table class="sp-event-blocks">` and call `get_kpl_fixtures()` — it logs "No fixtures table found on the page." and returns `False`. (A non-200 or missing variable produces different messages, so the observed log line confirms a 200-without-table response.)

## Blast radius
`get_kpl_fixtures` (`fixtures.py:444-446`) is the only caller, but the `Fixture` rows it would write feed `update_active_gameweek` (`fixtures.py:426` → `gameweeks.set_active_gameweek_from_fixtures`, `gameweeks.py:258`) and the lineup scraper `scan_upcoming_fixtures_for_lineups` (`lineups.py:168`), so gameweek activation and transfer deadlines silently stop updating. The env-var guard is missing only here — `standings.py` and `players.py` already have it, so no other site needs that part of the fix.

## Likely cause commit
Unclear — none of the listed commits touch the scraping logic: the newest (`a5a4379`, `38a2ca3`) are black/isort auto-format, the rest are ALLOWED_HOSTS pinning, incident reports, and CI wiring. The trigger is the external page no longer rendering the expected SportPress table, which no repo commit could cause.

## Applied fix
- `apps/kpl/tasks/fixtures.py:281-283` — added the `if not url:` guard for `TEAM_FIXTURES_URL`, matching `standings.py:21-24` / `players.py:77-79`: an unset variable now logs a clear message and returns `False` without hitting the network (previously `requests.get(None)` raised `MissingSchema`, swallowed into a confusing "Error fetching fixtures" line).
- `apps/kpl/tasks/fixtures.py:286` — added `timeout=30` to the request, matching `standings.py:250`.
- `apps/kpl/tasks/fixtures.py:296` — when the table is missing, logs `HTML preview (first 1000 chars): {web_content.text[:1000]}`, matching `standings.py:232-235`, so the next failure carries the actual page markup instead of a bare message.
- `tests/test_fixtures_scraper.py` (new) — `test_unset_url_is_reported_without_a_request` (fails before: the mock proves `requests.get` was still being called with `None`) and `test_missing_table_logs_html_preview` (fails before: the preview line was not logged). Both pass after the change and touch no database.

Verify with `pytest tests/test_fixtures_scraper.py`, then `flake8 .`, `black --check`, `isort . --check-only` as CI runs them.
