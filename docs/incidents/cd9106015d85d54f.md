# `get_user_team` answers `{"detail": ...}` instead of `[]` for a teamless user, so the Team page renders nothing

## Verdict
defect — `apps/fantasy/views.py:80` breaks the list contract of `GET /fantasy/teams/user-team`: the frontend types `userTeam` as `FantasyTeam[]` and every render guard in `TeamView.vue` compares `.length`, which is `undefined` on the dict the endpoint returns, so neither the team view nor the empty state ever renders.

## What happened
A logged-in user with no fantasy team opened the Team page and saw a blank page. The request succeeded (HTTP 200) but carried a `{"detail": "No fantasy team found for this user."}` object, which the store wrote into `userTeam`; `TeamView.vue`'s three branches all keyed on `.length` and all evaluated false, so nothing rendered. Separately, the page-level loading spinners on the Team and Standings pages did not match the homepage's.

## Root cause
`apps/fantasy/views.py:79-80` (in `FantasyTeamViewSet.get_user_team`):
```python
if not teams.exists():
    return Response([], status=status.HTTP_200_OK)
```
It previously returned `{"detail": "No fantasy team found for this user."}` with 200. The endpoint is a list endpoint (the non-empty branch returns `serializer.data` of `many=True`), but the empty branch returned a dict. The frontend assumes the array shape it declared — `client/src/stores/fantasy.ts:64` does `this.userTeam = response.data` into `userTeam: [] as FantasyTeam[]` — so `TeamView.vue:165` (`userTeam.length === 0`) and `TeamView.vue:3/:75` (`userTeam.length > 0`) all get `undefined` comparisons and stay false; `TeamView.vue:284-315` skips the `fetchAvailableGameweeks`/player-loading branch for the same reason, and the page is blank.

The loader inconsistency is the same class of drift: `HomeView.vue:5` and `FixturesView.vue:6` use `h-16 w-16 border-b-2 border-gray-900`, while `TeamView.vue:68` used `h-12 w-12 border-b-2 border-blue-600` and `StandingsView.vue:4` used `h-12 w-12 border-t-2 border-b-2 border-green-500` (with no text).

## How to reproduce
1. Log in as a user with no `FantasyTeam` rows.
2. Open `/team` (or any route rendering `TeamView.vue`).
3. Observe: no spinner, no team, no "Build Your KPL Fantasy Team!" empty state — blank content area. Network tab shows `GET /api/v1/fantasy/teams/user-team/` → 200 with a JSON object, not an array.

## Blast radius
Every consumer of `GET /fantasy/teams/user-team` assumes an array: `TeamView.vue` (`.length`, `[0]`) and `components/Team/SideBar.vue:280` (`userTeam[0]`). The sibling endpoint `apps/fantasy/views.py:146-149` (`team-players`) returns the same `{detail: ...}`-with-200 shape; its frontend consumer (`fetchFantasyTeamPlayers`, `fantasy.ts:133-140`) already defends with an `Array.isArray` check, so it is only cosmetically inconsistent.

## Applied fix
- `apps/fantasy/views.py:80` — the no-team branch now returns `Response([], status=status.HTTP_200_OK)`, restoring the array contract. `userTeam` stays `[]`, so `TeamView.vue:165` renders the "Build Your KPL Fantasy Team!" empty state exactly as designed.
- `client/src/views/TeamView.vue:68` — page loader spinner changed to `animate-spin rounded-full h-16 w-16 border-b-2 border-gray-900 mx-auto`, identical to `HomeView.vue:5`.
- `client/src/views/StandingsView.vue:4-7` — loader now matches the homepage markup (same spinner classes plus the `Loading ...` text); it previously had a smaller green ring and no text.
- `tests/test_fantasy_user_team.py` — new regression test: creates a user with no team, calls `/api/v1/fantasy/teams/user-team/` via DRF `APIClient` with a locmem cache override (the view reads Redis directly at `views.py:71`), and asserts `response.data == []`. This fails on the old code (asserts `[] == {"detail": ...}`) and passes now. Run with `pytest tests/test_fantasy_user_team.py` (needs a database, per `pytest.ini` → `config.settings.development`).
