# `config/settings/production.py` inherited `ALLOWED_HOSTS` from a base default of `"*"` — production served any `Host` header until the domains were pinned in code

## Summary

`config/settings/base.py:58-60` parses `ALLOWED_HOSTS` from the environment and falls back to `"*"` when the variable is unset. Nothing in the repository ever set that variable for production — not `docker-compose.prod.yml`, not (verifiably) `.env.example` — so whether prod accepted arbitrary Host headers depended entirely on the gitignored server-side `.env.prod`. Worse, a `.env.prod` copied from `.env.example` typically contains `ALLOWED_HOSTS=` with no value; an empty string *is* set, so the wildcard default never fires, the list parses to `[]`, and Django rejects every request with `DisallowedHost`. Both failure modes are silent. Fixed by pinning the hosts in `config/settings/production.py` (`SERVED_DOMAINS` + `pinned_hosts()`), with regression tests in `tests/test_allowed_hosts.py` that tie the pin to the domains nginx actually serves.

## What happened

| Layer | State before the fix |
|---|---|
| `config/settings/base.py:58-60` | `ALLOWED_HOSTS = [h.strip() for h in re.split(r"[,\s]+", env("ALLOWED_HOSTS", "*")) if h.strip()]` — correct parsing, wildcard default |
| `docker-compose.prod.yml:12-15` | Only `env_file: .env.prod`; no `ALLOWED_HOSTS` key in `environment:` |
| `.env.prod` | Gitignored, lives only on the VPS — unverifiable from the repo |

The real host list existed in the repo (nginx.conf) but was never connected to Django.

## Root cause

1. The `bb1261de30d1dac3` fix kept `"*"` as the default "so dev/CI behave exactly as before" — but production inherited the same default, and dev/CI are precisely where a wildcard is tolerable.
2. No repo artifact prompts the maintainer of `.env.prod` to set the variable, so its absence went unnoticed.
3. The failure is silent in both directions: with `USE_X_FORWARDED_HOST = True` (`production.py:61`) and `DEBUG` correctly boolean-coerced (`base.py:47`), a wildcard produces no error and no log line — Django simply accepts whatever Host an attacker sends. An empty value produces no warning either, just universal 400s.

## Impact

With `ALLOWED_HOSTS = ["*"]` behind `SECURE_HSTS_PRELOAD` (`production.py:70`):

- **Host-header poisoning** of the absolute URLs this app builds — the Google OAuth `redirect_uri` values at `apps/accounts/views.py:39,92,151` are built from `BASE_BACKEND_URL`, and email link generation trusts the request host.
- **Cache poisoning** where any intermediary caches per-Host.
- Combined with `SECURE_PROXY_SSL_HEADER` trusting `X-Forwarded-Proto` (`production.py:60`), client-supplied routing metadata was trusted end-to-end.

The `[]` variant was an outage waiting on one bad copy-paste of `.env.example`.

## Applied fix

Commit `994136b` — three parts:

1. **Pin in production** (`config/settings/production.py:45-54`):

   ```python
   SERVED_DOMAINS = ["fantasykenya.com", "www.fantasykenya.com"]

   def pinned_hosts(hosts, fallback):
       """`hosts` without the wildcard, or `fallback` when nothing is left."""
       named = [host for host in hosts if host != "*"]
       return named or list(fallback)

   ALLOWED_HOSTS = pinned_hosts(ALLOWED_HOSTS, SERVED_DOMAINS)
   ```
