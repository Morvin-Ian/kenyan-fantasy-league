# `get_gameweek_selection` answers 500 with `'NoneType' object has no attribute 'number'` when a new team has no selection and no gameweek is active — `apps/fantasy/views.py:199`

## Verdict

defect — `apps/fantasy/views.py:183-200` dereferences `gameweek.number` when `gameweek` resolved to `None`, so `GET /api/v1/fantasy/players/gameweek-players/` returns HTTP 500 (re-wrapped by the blanket `except Exception` at `views.py:213-217`) for every user who has a fantasy team but no `TeamSelection` while no `Gameweek` is active, and the Team page shows an error with no players instead of the expected empty/`"No team selection found"` response.

## What happened

A user who has created a fantasy team but has not yet saved a lineup opens the Team page during a window in which no gameweek is active (before the first `update_active_gameweek` beat run, between seasons, or when the Thursday-midnight beat task fails). `TeamView.vue` → `fetchFantasyTeamPlayers` (`client/src/stores/fantasy.ts:117-148`) calls `GET /fantasy/players/gameweek-players/`. The view resolves `gameweek` to `None` (no last selection, no active gameweek), queries `TeamSelection.objects.get(fantasy_team=..., gameweek=None)`, hits `TeamSelection.DoesNotExist`, and then formats the success response from `gameweek.number` — crashing with `AttributeError: 'NoneType' object has no attribute 'number'`. The outer `except Exception` at `views.py:213` converts that into HTTP 500 with the internal message leaked in the body. The store's `catch` sets `this.error` and `this.fantasyPlayers = []`, so the Team page renders an error/empty players state instead of the designed "No team selection found" flow.

The same endpoint also 500s on `?gameweek=abc`: `Gameweek.objects.get(number="abc")` raises `ValueError` (not `Gameweek.DoesNotExist`), which only the generic handler catches.

## Root cause

`apps/fantasy/views.py:159-183` — gameweek resolution can end with `gameweek = None`, and nothing guards it before the query or in the `DoesNotExist` handler:

```python
else:
    last_selection = (
        TeamSelection.objects.filter(fantasy_team=fantasy_team)
        .select_related("gameweek")
        .order_by("-gameweek__number")
        .first()
    )
    gameweek = last_selection.gameweek if last_selection else None
    if not gameweek:
        gameweek = Gameweek.objects.filter(is_active=True).first()
    # gameweek may still be None here

try:
    team_selection = (
        TeamSelection.objects.prefetch_related(...)
        .select_related("captain", "vice_captain")
        .get(fantasy_team=fantasy_team, gameweek=gameweek)   # line 183
    )
    ...
except TeamSelection.DoesNotExist:
    return Response(
        {
            "detail": f"No team selection found for gameweek {gameweek.number}",  # line 199
            "gameweek": gameweek.number,                                          # line 200
        },
        status=status.HTTP_200_OK,
    )
```

`gameweek=None` translates to a `gameweek__isnull=True` filter; `TeamSelection.gameweek` is a non-nullable FK (`apps/fantasy/models.py:232-234`), so no row can match and `.get()` raises `DoesNotExist`. The handler then dereferences `gameweek.number` on `None`. There is no `if not gameweek:` guard anywhere between line 172 and the `DoesNotExist` handler, and the `except Exception` at lines 213-217 converts the resulting `AttributeError` (and the `ValueError` from a non-numeric `?gameweek=`) into a 500 while echoing `str(e)` to the client.

## How to reproduce

1. Start from a database containing a `User`, a `FantasyTeam` for that user, zero `TeamSelection` rows, and no `Gameweek` with `is_active=True`.
2. Authenticate and call `GET /api/v1/fantasy/players/gameweek-players/`.
3. Observe HTTP 500 with body `{"detail": "An unexpected error occurred.", "error": "'NoneType' object has no attribute 'number'"}`.
4. Also observe `GET /api/v1/fantasy/players/gameweek-players/?gameweek=abc` returning HTTP 500 with `"error": "Field 'number' expected a number but got 'abc'."` (a `ValueError` escaping as a 500).

## Blast radius

- Every Team page load for a team with no saved selection whenever no gameweek is active: `client/src/stores/fantasy.ts:125-147` lands in `catch`, sets `this.error`, clears `fantasyPlayers`, and the Team view shows a failure/empty players area instead of the normal "pick your squad" state.
- The failure is state-dependent and intermittent by design of the beat schedule (`config/settings/base.py:383-386`, `update-kpl-gameweek` runs Thursday 00:00), so it appears/disappears without any code change — hard to diagnose from the frontend.
- The sibling `available-gameweeks` endpoint (`views.py:219-262`) handles the same empty state gracefully (returns `[]`), so the UI shows an empty gameweek selector while the players call 500s — inconsistent and confusing.
- The blanket `except Exception as e` at `views.py:213-217` leaks internal exception text (`str(e)`) to API consumers and masks unrelated errors behind the same generic 500.

## Applied fix

- `apps/fantasy/views.py` — after gameweek resolution (after line 171), return the designed empty response when no gameweek exists, before the query:

  ```python
  if not gameweek:
      return Response(
          {"detail": "No gameweek available.", "gameweek": None},
          status=status.HTTP_200_OK,
      )
  ```

- `apps/fantasy/views.py:160` — treat a non-numeric `gameweek` param as a client error instead of a 500 (e.g. catch `ValueError` alongside `Gameweek.DoesNotExist` and return 404/400).
- `apps/fantasy/views.py:213-217` — narrow or log the generic `except Exception` instead of echoing `str(e)` into the response body.
- Add a regression test (mirroring `tests/test_fantasy_user_team.py`): create a user + team, no selections, no active gameweek, call `gameweek-players/`, assert HTTP 200 with `gameweek: None`; and assert `?gameweek=abc` returns 4xx, not 500.
