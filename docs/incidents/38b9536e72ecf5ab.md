# Production nginx keeps host-rejection rules stale for six hours in `docker-compose.prod.yml`

## Verdict
defect — production mounts the nginx configuration containing the unknown-host rejection, but waits up to six hours to reload it, allowing a running stale configuration to continue forwarding unsupported hosts to Django.

## What happened
A request with `Host: logon.fantasykenya.com` reached Django and was rejected by `CommonMiddleware` before any application view executed. The checked-out nginx configuration would reject that host with `444` before proxying, so the Django-side log indicates the running nginx process had not loaded the mounted host-rejection configuration. `docker-compose.prod.yml` only reloads nginx every six hours, prolonging that stale runtime state.

## Root cause
`docker-compose.prod.yml:66-67` mounted `docker/production/nginx/nginx.conf` into the running nginx container but delayed reloads:

```yaml
# Reload every 6h so renewed certs get picked up without a manual restart.
command: /bin/sh -c 'while :; do sleep 6h & wait $${!}; nginx -s reload; done & nginx -g "daemon off;"'
```

The configuration at `docker/production/nginx/nginx.conf:8-24` defines default HTTP and HTTPS servers that return `444`, and `:47-51` rejects a TLS request whose `$host` is not `fantasykenya.com` or `www.fantasykenya.com`. The compose command assumed six-hour reload latency was acceptable for mounted edge-policy changes. That assumption does not hold: while nginx retains the old configuration, `/api/v1` and `/guardian` can still proxy an unsupported `Host` through `proxy_set_header Host $host` at `docker/production/nginx/nginx.conf:75-89`, where Django correctly raises `DisallowedHost`.

The traceback’s Django dependency files are outside this repository and could not be opened. It identifies Django `CommonMiddleware` calling `request.get_host()` as the surfacing path; the repository code establishes that the invalid host should have been stopped at nginx.

## How to reproduce
1. Run production with nginx holding a configuration from before the unknown-host rejection rules were loaded.
2. Update the mounted `docker/production/nginx/nginx.conf` with the current default-server and `$host` rejection blocks, without manually restarting or reloading nginx.
3. Within the previous six-hour reload interval, request a proxied path with:

```http
GET /api/v1/ HTTP/1.1
Host: logon.fantasykenya.com
```

The stale nginx worker can forward the host to Django, which rejects it with `DisallowedHost`. After nginx reloads the current configuration, it should close the connection with `444` instead.

## Blast radius
Every unsupported host sent to a Django-proxied route during the stale-config interval can produce the same API log entry. The affected proxy call sites are `/api/v1` and `/guardian` in `docker/production/nginx/nginx.conf:75-89`; static and Vue routes do not proxy to Django.

## Likely cause commit
39412aa (`maajun: incident report for Production nginx forwards unrecognised Host headers to Djang…`) most plausibly introduced the gap: it added the edge rejection configuration, while `docker-compose.prod.yml:67` retained the six-hour reload interval that delays application of mounted nginx policy changes.

## Applied fix
- `docker-compose.prod.yml:66-67` now reloads nginx every five minutes rather than every six hours, so the mounted default-server and host-rejection rules become active promptly while retaining periodic certificate reloads.
- `tests/test_allowed_hosts.py:119-126` now verifies that the production compose command uses a five-minute nginx reload interval and still invokes `nginx -s reload`.

Verification is to run the repository test suite including `tests/test_allowed_hosts.py`, deploy the compose change, and request `/api/v1/` with `Host: logon.fantasykenya.com` after the next reload. Nginx should close the connection with `444`, and no matching `django.security.DisallowedHost` log entry should occur. I could not execute tests, Docker Compose, or reload nginx because this environment provides no command-execution tool.
