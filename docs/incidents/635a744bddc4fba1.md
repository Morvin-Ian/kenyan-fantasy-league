# Production `ALLOWED_HOSTS` still resolves to the wildcard fallback — `config/settings/production.py` imports the unpinned value from `base.py` and never overrides it, so Django accepts any `Host` header behind HSTS preload

## What happened

Production serves requests with `ALLOWED_HOSTS = ["*"]`. The incident report `docs/incidents/47fa8ad55a8e4253.md` prescribed a fix (pin the real domains in `config/settings/production.py`, document the variable in `.env.example`, add a regression test), but only item 3 landed: `tests/test_allowed_hosts.py` exists and imports a `pinned_hosts` helper and a `SERVED_DOMAINS` constant from `config.settings.production` — **neither of which is defined in that module**. The settings change itself was never applied.

## Root cause

Tracing every layer the value could come from:

| Layer | State |
|---|---|
| `config/settings/base.py:58-60` | Parses `ALLOWED_HOSTS` from env via `env("ALLOWED_HOSTS", "*")` — correct parsing, **defaults to `"*"` when unset** |
| `config/settings/production.py` | Starts with `from .base import *` and never reassigns `ALLOWED_HOSTS`; contains no `SERVED_DOMAINS` and no `pinned_hosts` |
| `.env.example` | Cannot be inspected here (credential-protected placeholder; per repo history it does not document `ALLOWED_HOSTS`) |
| `docker-compose.prod.yml` | No `ALLOWED_HOSTS` in any `environment:` block (`api`, `celery_worker`, `celery_beat` all rely solely on `env_file: .env.prod`) |
| `.env.prod` | Gitignored, server-side — unverifiable from the repo |
| `docker/production/nginx/nginx.conf:8,24` | `server_name fantasykenya.com www.fantasykenya.com;` — the domains prod actually serves |

So whether production accepts arbitrary Host headers depends entirely on whether someone remembered to set `ALLOWED_HOSTS` in the gitignored `.env.prod`. Nothing in the repository enforces or documents it. A second silent failure mode: a `.env.prod` copied from a template with `ALLOWED_HOSTS=` (blank) parses to `[]`, which makes Django reject **every** request with `DisallowedHost`.

The regression test proves the gap rather than guarding against it — running `pytest tests/test_allowed_hosts.py` today fails at collection with:

```
ImportError while importing test module '...tests/test_allowed_hosts.py'
from config.settings.production import ALLOWED_HOSTS, SERVED_DOMAINS, pinned_hosts
ImportError: cannot import name 'SERVED_DOMAINS' from 'config.settings.production'
```

## Impact

With `ALLOWED_HOSTS = ["*"]` in production:

- **Host-header poisoning**: password-reset and activation links built from the request host can be pointed at attacker-controlled domains (the app builds such links in `apps/accounts`).
- **Cache poisoning** if any intermediary caches per-Host.
- Django classifies `ALLOWED_HOSTS` as a security control; combined with `USE_X_FORWARDED_HOST = True` (`production.py:36`) and `SECURE_PROXY_SSL_HEADER` trusting `X-Forwarded-Proto`, client-supplied routing metadata is trusted end-to-end.
- The blank-value variant is an outage: every request 400s with `DisallowedHost`.

## Suggested fix

**1. Pin production explicitly** — in `config/settings/production.py`, after `from .base import *`:

```python
import re

def pinned_hosts(configured, served):
    """Configured hosts win; wildcard/empty fall back to what nginx serves."""
    cleaned = [h for h in configured if h != "*"]
    return list(cleaned) if cleaned else list(served)

SERVED_DOMAINS = ["fantasykenya.com", "www.fantasykenya.com"]

ALLOWED_HOSTS = pinned_hosts(
    [h.strip() for h in re.split(r"[,\s]+", os.getenv("ALLOWED_HOSTS", "")) if h.strip()],
    SERVED_DOMAINS,
)
```

This kills both failure modes: unset → real domains instead of `"*"`; blank → real domains instead of `[]`; an explicit override (e.g. staging naming its own host) still wins; a mixed `"*, fantasykenya.com"` loses the wildcard. Returning copies prevents callers mutating `SERVED_DOMAINS` through the result.

**2. Document the variable** in `.env.example`:

```
# Comma/space-separated hosts Django will serve. REQUIRED in production.
ALLOWED_HOSTS=fantasykenya.com,www.fantasykenya.com
```

**3. Keep the existing regression test as-is** — once item 1 lands, all eight tests in `tests/test_allowed_hosts.py` pass, including the one that cross-checks `SERVED_DOMAINS` against `server_name` lines parsed out of `docker/production/nginx/nginx.conf`, so moving domains has to move both files together.

## Applied fix

Not yet applied — this report documents the gap and the concrete patch. Item 1 is load-bearing; items 2–3 prevent recurrence.
