## What happened

The CI/CD run on commit `77eef8b9` (the merge of PR #84, which added `tests/test_google_oauth_env.py`) failed in the `backend-checks` job. The new file imports `pytest` at line 21 but never references it: no `@pytest.mark.*`, no `pytest.raises` — the two `monkeypatch` fixtures (lines 62, 68) are injected by pytest itself and need no import. `flake8 .` (`.github/workflows/ci.yml:45`) therefore flags `F401 'pytest' imported but unused`. F401 is **not** suppressed anywhere: `setup.cfg` only ignores `E203`/`E501` globally and `F403`/`F405` for the two settings modules, so the unused import fails the very first step of the backend pipeline.

A second, latent failure was in the same file: `isort . --check-only` (ci.yml:49) wants from-imports ordered by module name, so `from config.settings.base import env` must precede `from pathlib import Path` (`config` < `pathlib`). The file as merged had `pathlib` first, which would also fail isort — the file would have failed two of the four backend steps.

## Root cause

Incident `92d7c9df635b2e17` shipped the regression test to close the "no test guards the Google OAuth env contract" gap, but verified it only by re-reading the source, explicitly without running the repo's own gates (`pytest` could not be executed). Nothing in that verification exercised the linters the CI workflow runs *before* pytest. The authoring convention was matched to the sibling source-assertion tests, but the repo's import hygiene rules were not: every sibling either uses `pytest` (`test_entrypoint.py`, `test_custom_user_manager.py`, `test_fantasy_user_team.py`) or does not import it at all (`test_allowed_hosts.py`), and none carries an unused import. The merge was green-checked only on the basis of the incident doc, so a file that could never pass `flake8 .` / `isort --check-only` landed on master and broke the pipeline.

## Applied fix

Changed exactly two files:

1. **`tests/test_google_oauth_env.py`** — removed the unused `import pytest` (line 21) and reordered the from-imports to isort order (`from config.settings.base import env` before `from pathlib import Path`). No test body changed: the `monkeypatch` fixtures continue to work without the import, and all seven assertions are byte-for-byte identical.
2. **`docs/incidents/5c4e7a2b9d8f6013.md`** — this record.
