# Production host configuration omits `manager.fantasykenya.com` in `config/settings/production.py`

## Verdict
defect — the deployment received traffic for `manager.fantasykenya.com`, but production settings and nginx did not recognize that hostname, allowing Django’s host-validation rejection to escape as an application error.

## What happened
A user or client requested the deployment with `Host: manager.fantasykenya.com`. Nginx did not recognize that name in its configured KFL virtual host, while Django’s `CommonMiddleware` received the host on a proxied request and rejected it before any view ran. The requester received Django’s rejected-host response and the deployment logged `django.security.DisallowedHost`.

## Root cause
`config/settings/production.py:45-58` declared the production-host floor without the hostname from the error:

```python
SERVED_DOMAINS = [
    "fantasykenya.com",
    "www.fantasykenya.com",
    "manager.fantasykenya.com",
]
...
ALLOWED_HOSTS = pinned_hosts(ALLOWED_HOSTS, SERVED_DOMAINS)
```

Before this change, `SERVED_DOMAINS` included only `fantasykenya.com` and `www.fantasykenya.com`; `pinned_hosts()` therefore produced an `ALLOWED_HOSTS` list that omitted `manager.fantasykenya.com`. The failed assumption was that only those two KFL hostnames would reach the deployment. That does not hold for the observed production request.

The edge configuration made the same omission: the application server names and unknown-host guard in `docker/production/nginx/nginx.conf:27-50` previously omitted `manager.fantasykenya.com`. Its proxied API locations preserve the incoming hostname with `proxy_set_header Host $host` (`docker/production/nginx/nginx.conf:75-88`), so a host nginx accepted must also be accepted by Django.

The Django dependency files named in the traceback are outside this repository and could not be read. The traceback identifies Django `CommonMiddleware.process_request()` calling `request.get_host()` as the surfacing path; no application view is implicated.

## How to reproduce
Request either Django-proxied route through the production edge with:

```http
GET /api/v1/ HTTP/1.1
Host: manager.fantasykenya.com
```

Before this change, the production host allowlist did not contain that hostname, so Django raised `DisallowedHost`.

## Blast radius
Every request to `/api/v1` or `/guardian` using `manager.fantasykenya.com` could produce the same rejection. Other environment-configured hosts previously replaced the served-domain fallback entirely; `pinned_hosts()` now retains all repository-defined production domains alongside explicitly configured hosts.

## Likely cause commit
27cbf1f (`feat: serve mogul.manager from the shared nginx edge`) most plausibly introduced the hostname-routing gap: it added the separate `mogul.fantasykenya.com` edge configuration (`docker/production/nginx/mogul.conf:27-44`) without defining the observed `manager.fantasykenya.com` hostname in the KFL edge or Django host floor.

## Applied fix
- `config/settings/production.py:45-58` now includes `manager.fantasykenya.com` in `SERVED_DOMAINS`; `pinned_hosts()` now appends every required served domain to non-wildcard environment hosts, ensuring a configured value cannot remove the production hostname floor.
- `docker/production/nginx/nginx.conf:27-50` now declares `manager.fantasykenya.com` in both HTTP and HTTPS application `server_name` directives and accepts it in the HTTPS unknown-host guard, so nginx can redirect and proxy the hostname that Django now accepts.
- `tests/test_allowed_hosts.py:84-126` now verifies that configured hosts retain the required served domains, the wildcard path produces the full served-domain list, nginx’s guard contains the manager hostname, and production `ALLOWED_HOSTS` explicitly includes it.

Verify by running `pytest tests/test_allowed_hosts.py`, reloading the production nginx configuration, and requesting `/api/v1/` with `Host: manager.fantasykenya.com`; Django should no longer emit `DisallowedHost`. I could not execute tests or reload nginx because this environment has no command-execution tool.
