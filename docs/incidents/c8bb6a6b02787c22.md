# apps/fantasy/views.py assumes an active gameweek exists before reporting a missing selection

## Verdict
defect — a valid authenticated request during a period with no selections and no active gameweek dereferenced `None` and escaped as a 500.

## What happened
A user requested `GET /api/v1/fantasy/players/gameweek-players/` without a `gameweek` query parameter. When their team had no prior `TeamSelection` and the deployment had no `Gameweek(is_active=True)`, the endpoint attempted to construct its no-selection response using `gameweek.number`. Django logged the resulting internal server error for this endpoint.

## Root cause
`apps/fantasy/views.py:171-173` correctly permits both sources of a default gameweek to be absent:

```python
gameweek = last_selection.gameweek if last_selection else None
if not gameweek:
    gameweek = Gameweek.objects.filter(is_active=True).first()
```

Before this change, `apps/fantasy/views.py:204-210` then assumed `gameweek` was an object and evaluated `gameweek.number` in the `TeamSelection.DoesNotExist` handler. That assumption does not hold when the user has no saved selection and no active gameweek exists; `.first()` returns `None`, so accessing `.number` raises `AttributeError` and reaches the broad 500 handler at `apps/fantasy/views.py:221-225`.

## How to reproduce
1. Create and authenticate a user with a `FantasyTeam`.
2. Ensure that team has no `TeamSelection` records.
3. Ensure no `Gameweek` has `is_active=True`.
4. Request `GET /api/v1/fantasy/players/gameweek-players/` without `?gameweek=`.

Before the fix, this reaches the missing-selection handler and raises while reading `None.number`; after it, it returns HTTP 404 with `{"detail": "No active gameweek found."}`.

## Blast radius
This affects every team owner requesting the endpoint without `gameweek` while they have no prior selection and the system has no active gameweek. The only route to `get_gameweek_selection` is the `gameweek-players` action declared at `apps/fantasy/views.py:155-156`; no other call sites for this method exist in the repository.

## Likely cause commit
Unclear — none of the supplied commits touch `apps/fantasy/views.py` according to the available repository inspection.

## Applied fix
- `apps/fantasy/views.py:175-179` now returns a deliberate HTTP 404 response immediately when neither a previous selection nor an active gameweek supplies a gameweek, before the code can dereference it.
- `tests/test_fantasy_user_team.py:77-94` now covers an authenticated team owner with no gameweeks and asserts the endpoint returns the new 404 payload.

Verification: run `pytest tests/test_fantasy_user_team.py`; the added regression test exercises the previously failing no-active-gameweek path.
