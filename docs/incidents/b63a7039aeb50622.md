# `.env.example` omits the required `TEAM_FIXTURES_URL` configuration for the Celery fixture scraper

## Verdict
defect — the scheduled worker depends on `TEAM_FIXTURES_URL`, but the repository’s environment template did not tell deployment operators to provide it.

## What happened
The Celery worker ran the scheduled fixture scrape and logged `No fixtures table found on the page`, then returned `False` without creating or updating `Fixture` rows. The exact logged text is not present in the current task implementation: `apps/kpl/tasks/fixtures.py:299-305` now emits URL, response-status, and response-size diagnostics, indicating the running deployment had not yet incorporated that hardening.

## Root cause
The deployment configuration contract was incomplete at `.env.example:1-25`: it listed broker and backend settings but omitted `TEAM_FIXTURES_URL`, despite `config/settings/base.py:407-410` requiring it and `apps/kpl/tasks/fixtures.py:278-287` consuming it.

```python
TEAM_FIXTURES_URL = env("TEAM_FIXTURES_URL")
```

```python
url = base.TEAM_FIXTURES_URL

if not url:
    logger.error(
        "TEAM_FIXTURES_URL is not set ..."
    )
    return False
```

The unmet assumption was that operators would know to add the source URL despite it not being documented in the checked-in environment template. The prior worker implementation represented by the reported log also assumed the fetched HTTP-200 document would contain `table.sp-event-blocks`; this can fail for an incorrect source URL, source markup drift, or a login/error page. The supplied error contains no URL, response body, HTTP status beyond the old implementation’s implicit success path, or deployed revision, so the specific live response cannot be determined.

## How to reproduce
Start the production worker using an environment file derived from the pre-fix `.env.example`, without `TEAM_FIXTURES_URL`, or configure it with a URL that returns an HTTP-200 page without `table.sp-event-blocks`; then allow the `update-kpl-fixtures` beat task configured at `config/settings/base.py:379-382` to run. The old deployed task logs the reported generic error; the current task reports the configured URL and response metadata instead.

## Blast radius
All deployments that construct `.env` or `.env.prod` from `.env.example` could omit the fixture source and leave fixture data stale. The only in-repository call path is Celery beat’s `get_kpl_fixtures` task (`config/settings/base.py:379-382` → `apps/kpl/tasks/fixtures.py:457-459`); no additional call sites for `extract_fixtures_data` were found.

## Likely cause commit
Unclear — none of the supplied recent commits can be verified as introducing the missing template entry; the related `9bae30d` incident commit appears to have added the settings/task hardening already present in this checkout, while the reported legacy log proves the live worker was running code without that change.

## Applied fix
- `.env.example:27-28` now documents `TEAM_FIXTURES_URL` and identifies the required SportPress table, so an environment file used by the Docker worker can supply the source required by `config/settings/base.py:410`.
- `tests/test_fixtures_url_config.py:1-18` was added to assert that the environment template documents the setting and that the settings module and fixture task use the same hardened configuration path.

Verification is by running the added pytest module and deploying the current task code with `TEAM_FIXTURES_URL` set to the KPL fixtures page; a source page without the expected table now logs the URL, HTTP status, and body size at `apps/kpl/tasks/fixtures.py:299-305`.
