# `apps/kpl/tasks/fixtures.py` scraped a raw `os.getenv("TEAM_FIXTURES_URL")` with no default or trimming, then logged an unactionable "No fixtures table found" when the env var was unset or whitespace-corrupted by docker-compose `env_file` — the same unhardened pattern incident `bb1261de30d1dac3` was written to eliminate

**Summary:** The `docker:worker` error `No fixtures table found on the page.` (fingerprint `b63a7039aeb50622`) is the KPL fixtures scraper failing in the exact failure family documented in incident `bb1261de30d1dac3`: `apps/kpl/tasks/fixtures.py:280` re-read `TEAM_FIXTURES_URL` with bare `os.getenv()` (no default, no trim, no validation) instead of the whitespace-tolerant `env()` helper, so an unset or whitespace-padded variable made the worker fetch nothing/`None` — and the subsequent log gave no URL, no status, and no hint, so the outage surfaced only as a one-line error every scheduled run.

## What happened

Every time the celery beat schedule ran `get_kpl_fixtures` (via `extract_fixtures_data`), the worker logged:

```
[ERROR] apps.kpl.tasks.fixtures: No fixtures table found on the page.
```

and returned `False`, so no `Fixture` rows were created or updated. The scraping pipeline (fixtures → gameweek activation → live-game monitoring) silently stalled. The error repeated every run because nothing in the repository validated or trimmed the URL config.

## Root cause

Two defects in `apps/kpl/tasks/fixtures.py` compounded:

1. **Raw, unvalidated env read (`extract_fixtures_data`).** Line 280 was:

   ```python
   url = os.getenv("TEAM_FIXTURES_URL")
   ```

   - If `TEAM_FIXTURES_URL` is unset, `url` is `None` and `requests.get(None, ...)` raises `MissingSchema`, swallowed by the `except requests.RequestException` branch — silently returning `False` with only a generic "Error fetching fixtures".
   - If it carries stray whitespace (docker-compose's `env_file:` passes values verbatim — the premise documented in `config/settings/base.py:32-40`), the URL is corrupted and the worker fetches the wrong page, which has no `sp-event-blocks` table.
   - The hardened `env()` helper and the pattern of importing `config.settings.base` already existed (used by `apps/kpl/tasks/standings.py:11`, `base.DEFAULT_LOGGING`, `base.GOOGLE_*` after the prior incident), but `fixtures.py` never adopted it.

2. **Single fragile, non-actionable failure log.** The only structure check was:

   ```python
   table = soup.find("table", class_="sp-event-blocks")
   if not table:
       logger.error("No fixtures table found on the page.")
       return False
   ```

   The log omitted the URL, the HTTP status, and the response size, and gave no guidance — so a misconfigured env var and a source-site markup change were indistinguishable, and neither was diagnosable from the log.

Additionally, `import os` at the top of `fixtures.py` existed solely for that one raw `getenv` (no other `os.` use in the file).

## How to reproduce

1. In `.env` / `.env.prod`, leave `TEAM_FIXTURES_URL` unset, or add a trailing space to it (invisible in editors; preserved by `env_file:`).
2. Restart the worker stack and trigger the scheduled `get_kpl_fixtures` task.
3. Observe `[ERROR] apps.kpl.tasks.fixtures: No fixtures table found on the page.` (or the swallowed `MissingSchema` path) with no URL in the log; `Fixture` table stays stale.
4. Contrast the fixed behavior: a missing value now logs an explicit "TEAM_FIXTURES_URL is not set" error naming the env var and the file to edit.

## Blast radius

- **Silent data staleness in every environment**: fixture rows, the active gameweek, and downstream live-game monitoring all depend on this scrape. The task returns `False` without raising, so beat keeps retrying and nothing alerts.
- **Two independent failure entry points** share one opaque log line: unset variable and corrupted/whitespace-padded variable both end at "No fixtures table found" (or a swallowed exception), so even an experienced operator can't tell whether the fix is config or markup.
- **Same unhardened family is still latent elsewhere**: `apps/kpl/tasks/standings.py:21,244` (`TABLE_STANDINGS_URL`, `TEAM_LOGOS_URL`), `players.py:74`, and `live_games.py:834` (`MATCHES_URL`) still call raw `os.getenv` for URL config. They are the next occurrences of this incident; fixing them is follow-up scope, not part of this change.

## Likely cause commit

**Pre-existing.** `extract_fixtures_data` predates the `env()` hardening pass documented in `docs/incidents/bb1261de30d1dac3.md` and was never migrated to the settings-based single-source-of-truth pattern. The observed error is simply the first logged symptom of that stale code path.

## Suggested fix

Make `config.settings.base` the single source of truth (the pattern already proven by the OAuth fix and by `apps/kpl/tasks/standings.py:11`):

- Define `TEAM_FIXTURES_URL = env("TEAM_FIXTURES_URL")` in `config/settings/base.py` so the value is trimmed and centrally documented.
- In `apps/kpl/tasks/fixtures.py`, read `base.TEAM_FIXTURES_URL`, bail out with an explicit message when it's empty, and enrich the "no table" log with the URL, status, and byte count.

## Applied fix

Changed **two files**:

1. **`config/settings/base.py`** — added the hardened single source of truth next to the Google credentials (line 410):

   ```python
   # KPL fixtures scraping source (SportPress "sp-event-blocks" table). Read through
   # env() so stray whitespace in .env / .env.prod (passed verbatim by docker-compose
   # env_file) cannot corrupt the URL; the celery worker must use this, not raw os.getenv.
   TEAM_FIXTURES_URL = env("TEAM_FIXTURES_URL")
   ```

2. **`apps/kpl/tasks/fixtures.py`**:
   - Removed the now-unused `import os` (the file's only `os.` usage was the raw `getenv`).
   - `extract_fixtures_data` now reads `url = base.TEAM_FIXTURES_URL` (line 279) instead of `os.getenv("TEAM_FIXTURES_URL")`.
   - Added an explicit guard: if `TEAM_FIXTURES_URL` is empty, log an error naming the env var, the `.env`/`.env.prod` file to edit, and the need to restart the worker; return `False`.
   - Replaced the bare `"No fixtures table found on the page."` log with a diagnostic message that includes the URL, the HTTP status, the response size in bytes, and a checklist (`TEAM_FIXTURES_URL` correctness, SportPress markup drift, login-wall/error page). The `requests.RequestException` branch now also includes the URL.

**Outside the repository:** the operator must ensure `TEAM_FIXTURES_URL` is set (to the KPL fixtures page URL) in `.env` / `.env.prod`; docker-compose's `env_file:` already injects it into the worker. I could not update `.env.example` to document it — that file is credential-gated and unreadable — but the new settings constant and the new log messages document it in-repo.

Verified post-edit: no `os.getenv` remains in `fixtures.py`, `base.TEAM_FIXTURES_URL` is the only read site in the module, and `grep TEAM_FIXTURES_URL` shows exactly the settings definition plus the task's use. Follow-up (unchanged here): migrate the same raw-`getenv` URL reads in `apps/kpl/tasks/standings.py`, `players.py`, and `live_games.py`.
