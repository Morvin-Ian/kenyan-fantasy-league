# Profile update fails with "Profile not found" for users who registered via Google auth

## What happened
A user who just registered through "Continue with Google" signed in and opened the profile page. When they edited their details and hit Save, the backend returned `404 {"detail": "Profile not found."}` and the update was never applied. Users who registered with email/password did not hit this error.

## Root cause
The profile-update flow breaks because the frontend sends the **user's UUID** where the backend expects the **profile's UUID**, and these are two different identifiers.

1. **Google OAuth returns the user id, not the profile id.** After a successful Google sign-in, `UserAuthService.prepare_user_response()` in `apps/accounts/services.py:118-128` builds the user payload with `"id": str(user.id)` — the `User.id` UUID. The frontend stores this object directly in `authStore.user` (`client/src/views/Auth/OAuthCallback.vue:61-62`).

2. **The real profile is never fetched for Google users.** `refreshUserProfile()` in `client/src/stores/auth.ts:197-200` bails out early with `if (this.user !== null && this.user !== undefined) return;`. Since the OAuth callback already set `user`, the app never calls `GET /api/v1/profile/`, which is the only place that returns the `Profile.id` UUID. (Email/password users have `authStore.user === null` after login, so `initialize()` → `refreshUserProfile()` fetches the profile and everything works — which is why only Google users are affected.)

3. **The frontend then passes the wrong id to the update endpoint.** `client/src/views/ProfileView.vue:218` calls `authStore.updateProfile(formData, user.value.id)`, and `client/src/stores/auth.ts:221` PATCHes `/profile/update/${uuid}/` with that id.

4. **The backend looks up a profile by that UUID.** `apps/profiles/views.py:37-43` (before the fix) did `Profile.objects.filter(id=uuid).first()`. `Profile.id` is its own UUID (`util/models.py:8`, via `TimeStampedUUIDModel`) and never equals `User.id`, so the lookup returns `None` and the view returns `"Profile not found."`

The profile object itself *does* exist for Google users (the `post_save` signal in `apps/profiles/signals.py:13-16` creates it, and `apps.profiles` is loaded in `INSTALLED_APPS` with `ready()` importing the signals). The failure is purely the id mismatch. A secondary flaw: the endpoint also trusted an arbitrary UUID in the URL and would let any authenticated user edit another user's profile (IDOR).

## Suggested fix
Make `UpdateProfileAPIView` resolve the profile from the authenticated request user — mirroring `GetProfileAPIView` (views.py:20-27) — instead of trusting the UUID in the URL. This fixes the Google-auth flow regardless of which id the frontend sends, and removes the IDOR hole:

```python
def patch(self, request, uuid):
    try:
        profile = Profile.objects.get(user=self.request.user)
    except Profile.DoesNotExist:
        return Response(
            {"detail": "Profile not found."}, status=status.HTTP_404_NOT_FOUND
        )

    data = request.data
    user = profile.user
    ...
```

(The `uuid` argument stays in the signature to match the URL pattern `<uuid:uuid>/`, but is no longer used for lookup.) A belt-and-braces frontend improvement would be to have `OAuthCallback.vue` refresh the real profile (or make `refreshUserProfile` always fetch), but the backend change alone resolves the reported error.

## Applied fix
Edited `apps/profiles/views.py`, `UpdateProfileAPIView.patch`:

- Replaced `profile = Profile.objects.filter(id=uuid).first()` + null check with `profile = Profile.objects.get(user=self.request.user)` wrapped in `Profile.DoesNotExist` → `404 "Profile not found."`
- Removed the dead `if profile.id != uuid` block (it could never trigger since the profile was fetched by that exact id).
- Re-indented the remainder of the method body and preserved the existing outer `try/except` for unexpected errors.

The endpoint now always updates the authenticated user's own profile, so the user id sent by the Google-auth frontend flow resolves correctly and the "Profile not found." error no longer occurs.
