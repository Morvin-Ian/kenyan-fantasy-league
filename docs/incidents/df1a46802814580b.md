# `apps/accounts/views.py` logs an expected incomplete Google OAuth callback as an error

## Verdict
defect — a missing authorization code is deliberately handled with a failure redirect, but `apps/accounts/views.py:95` misclassifies that expected rejected callback as an application error, generating false production-error alerts.

## What happened
A request reached `GET /api/v1/auth/google/callback/` without Google’s `code` parameter. The view redirected the browser to the frontend callback with `auth_success=false&auth_message=no_code`, where `client/src/views/Auth/OAuthCallback.vue:61-67` displays a sign-in failure rather than crashing. Despite that handled result, the API emitted the reported `[ERROR]` log event.

## Root cause
The defect was at `apps/accounts/views.py:93-99`:

```python
if not code:
    logger.error("No authorization code received from Google")
    error_url = (
        f"{redirect_to}?auth_success=false&auth_message=no_code&origin={origin}"
    )
    return redirect(error_url)
```

The code assumes that every missing `code` represents an operational error. That assumption does not hold: this branch is an intentional, handled rejection that returns a browser redirect, just like Google’s explicit denial branch at `apps/accounts/views.py:86-91`. Logging it at error severity caused the deployment’s error reporting to surface a normal incomplete OAuth flow as an incident.

## How to reproduce
Request `GET /api/v1/auth/google/callback/` without `code` or `error`. `apps/accounts/urls.py:11-15` routes it to `GoogleAuthCallbackView`; the view returns a redirect to the frontend callback with `auth_success=false&auth_message=no_code`.

## Blast radius
Every cancelled, incomplete, stale, manually visited, or externally probed Google callback URL without `code` and `error` previously produced a false `[ERROR]` event. Successful callbacks still exchange the received code at `apps/accounts/views.py:101-106`; explicit Google errors remain separately handled at `apps/accounts/views.py:86-91`.

## Likely cause commit
Unclear — none of the supplied commits can be tied to the inspected missing-code logging line without commit-to-line provenance, and the listed OAuth commits concern credentials or redirect token exposure rather than callback severity.

## Applied fix
- `apps/accounts/views.py:95` now logs the handled missing-code OAuth callback with `logger.warning(...)` instead of `logger.error(...)`, so expected failed authorization flows no longer appear as API errors while remaining visible for diagnostics.
- `tests/test_google_oauth_callback.py:1-14` was added to assert that the missing-code message uses warning severity and cannot regress to error severity.
