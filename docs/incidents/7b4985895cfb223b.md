# tests/test_entrypoint.py assumes credential environment assignments are forbidden

## Verdict
defect — the added regression test rejects the deliberate shell expansion used to construct Python’s environment, despite the heredoc itself being correctly quoted.

## What happened
Backend CI fails both parameterized instances of `test_postgres_ready_passes_credentials_via_environment`. The test reads each entrypoint and asserts that `${POSTGRES_DB}`, `${PG_USER}`, `${PG_PASSWORD}`, `${PG_HOST}`, and `${PG_PORT}` occur nowhere in the file. Both entrypoints intentionally contain those expansions in the command prefix that supplies environment variables to `python3`; the sensitive Python heredoc does not interpolate them.

## Root cause
The failing assertion in `tests/test_entrypoint.py:54-56` was previously applied to the entire entrypoint body:

```python
for var in INTERPOLATED:
    assert var not in body
```

That assumed no braced shell expansion could exist anywhere in the script. This does not hold: `docker/local/django/entrypoint:27-28` and `docker/production/django/entrypoint:27-28` deliberately expand validated shell variables while assigning them to the `python3` process environment:

```bash
POSTGRES_DB="$POSTGRES_DB" PG_USER="$PG_USER" PG_PASSWORD="$PG_PASSWORD" \
PG_HOST="$PG_HOST" PG_PORT="$PG_PORT" python3 - <<'END'
```

The security property is that the quoted heredoc body does not interpolate shell credentials; both entrypoints satisfy that property by reading values through `os.environ` at `docker/local/django/entrypoint:37-41` and `docker/production/django/entrypoint:37-41`.

## How to reproduce
Run the parameterized entrypoint test with pytest. Before the change, `tests/test_entrypoint.py::test_postgres_ready_passes_credentials_via_environment` fails for both the local and production entrypoints because each contains the intentional command-prefix assignments above.

## Blast radius
The failure affects backend CI because `.github/workflows/ci.yml:50-58` runs the full pytest suite. It affects both entrypoints listed in `tests/test_entrypoint.py:18-21`; application runtime behavior is not affected because the scripts correctly quote their heredocs.

## Applied fix
Changed `tests/test_entrypoint.py:51-56` so the no-shell-interpolation assertion examines only the content between `<<'END'` and the matching `END`, rather than the entire script. The test still verifies the quoted delimiter and `os.environ` reads, while accepting the necessary environment assignments before `python3`; verify by running the pytest entrypoint test and the full backend test suite.
