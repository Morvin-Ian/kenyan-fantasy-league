## Incident Report: Site-wide improvement review

**Error summary:** A review of the KPL Fantasy League codebase for improvement opportunities found three concrete, verifiable issues — one critical Django misconfiguration, one security hardening gap, and one duplicated network request. All three have been fixed.

### 1. Critical — `DEBUG` is parsed as a string, so it stays ON in production

**File:** `config/settings/base.py:34`

```python
DEBUG = os.getenv("DEBUG")   # before
DEBUG = os.getenv("DEBUG", "false").lower() == "true"   # after
```

**What happened / root cause:** `os.getenv("DEBUG")` returns the string `"False"` when the env file has `DEBUG=False`. In Python every non-empty string is truthy, so `DEBUG` was effectively `True` in production. The site would serve Django's verbose error pages (stack traces, settings, environment) to anyone who triggers a 500, and the debug page leaks configuration. The fix coerces the value to a real boolean, matching the pattern already used for `LINEUPS_SCRAPING_ENABLED` in the same file.

### 2. High — `ALLOWED_HOSTS = ["*"]` in all environments

**File:** `config/settings/base.py:47-48`

```python
# before
# ALLOWED_HOSTS = os.getenv("ALLOWED_HOSTS").split(" ")
ALLOWED_HOSTS = ["*"]

# after
ALLOWED_HOSTS = [h for h in os.getenv("ALLOWED_HOSTS", "*").split(" ") if h]
```

**What happened / root cause:** The env-driven configuration was commented out and replaced with a wildcard, which permits Host-header attacks and defeats Django's `ALLOWED_HOSTS` protection in production. The fix restores env-driven configuration while defaulting to `"*"` so existing dev/CI setups (which don't set the variable) behave exactly as before — but production can now pin its real domains.

### 3. Medium — Standings page fires the standings request twice on load

**File:** `client/src/views/StandingsView.vue`

**What happened / root cause:** The component had two independent triggers for the same fetch:
- a `watch(..., { immediate: true })` that calls `fetchStandings()` when the store is empty, and
- an `onMounted` block that also calls `fetchStandings()` when the store is empty.

Because the first call is async and hasn't completed by mount time, both fire, doubling the request against the API (and hammering the 24-hour cached `/kpl/standings/` endpoint). The duplicate `onMounted` call was removed — the immediate watch already guarantees a single fetch, and also handles the case where standings are later cleared.

### Minor observations (not changed)

- Leftover debug logging in production paths: `console.log(response)` in `stores/auth.ts:173`, `console.log("Ok")` at `stores/auth.ts:148`, and `console.log('Lineup uploaded successfully')` in `FixturesView.vue:221`.
- `authStore.updateProfile` reads `error.response.data.detail` without a guard — a missing response body would throw instead of showing a clean error.
- `SIMPLE_JWT.ACCESS_TOKEN_LIFETIME` is 1 day; consider shortening (e.g. 30–60 min) since the refresh-token flow in `axios-interceptor.ts` already handles rotation.

**Verification:** I cannot run the app or tests in this environment, so changes were validated by re-reading the edited files. The `DEBUG` fix is the highest-value change — it's a classic Django pitfall that silently disables production safety.
