# `ALLOWED_HOSTS` is still effectively `["*"]` in production — the env-driven fix never pins real domains, and prod's TLS/HSTS settings assume hosts that aren't configured anywhere

## Summary

`config/settings/base.py:58-60` now parses `ALLOWED_HOSTS` from the environment (fixing the earlier hardcoded wildcard), but **nothing sets `ALLOWED_HOSTS` for production**: it isn't in `.env.example`, isn't set anywhere in `docker-compose.prod.yml`, and no template documents it. Unless the gitignored server-side `.env.prod` happens to define it, production falls back to the `"*"` default — so Django accepts requests with any `Host` header while `SECURE_HSTS_PRELOAD`, `CSRF_TRUSTED_ORIGINS`, and nginx's `server_name fantasykenya.com` all assume exactly two domains. The hardening added on 2026-08-22 (`bb1261de30d1dac3`) is inert in the one environment that needs it.

## What happened

After the `ALLOWED_HOSTS = ["*"]` fix landed, production should resolve hosts from env. Tracing every place the value could come from shows the chain is broken for prod:

| Layer | State |
|---|---|
| `config/settings/base.py:58-60` | `ALLOWED_HOSTS = [h.strip() for h in re.split(r"[,\s]+", env("ALLOWED_HOSTS", "*")) if h.strip()]` — correct parsing, but defaults to wildcard when unset |
| `.env.example` | Does not document `ALLOWED_HOSTS` at all |
| `docker-compose.prod.yml` | No `ALLOWED_HOSTS` in `environment:`; relies entirely on `env_file: .env.prod` |
| `.env.prod` | Gitignored, lives only on the server — unverifiable from the repo |
| `docker/production/nginx/nginx.conf:24` | `server_name fantasykenya.com www.fantasykenya.com;` — the domains prod actually serves |
| `client/vite.config.ts:13-16` | Dev server allows the same two domains |

So the "real" host list exists in the repo — just not wired into Django.

## Root cause

1. The fix in `bb1261de30d1dac3` deliberately kept `"*"` as the default "so existing dev/CI setups behave exactly as before" — but dev/CI are precisely where a wildcard is tolerable. Production got no corresponding change.
2. `docker-compose.prod.yml` passes no `ALLOWED_HOSTS` key and `.env.example` doesn't list one, so nothing prompts whoever maintains `.env.prod` to set it. If they didn't, prod runs with `["*"]`.
3. The failure is silent: with `USE_X_FORWARDED_HOST = True` (`config/settings/production.py:36`) and `DEBUG` correctly coerced to boolean (`base.py:47`), there is no error, no warning, and no failed request — Django simply accepts any Host header an attacker sends.

## Impact

With `ALLOWED_HOSTS = ["*"]` behind HSTS preload:

- **Host-header attacks** become possible: password-reset and activation emails built with `DOMAIN`/request host can be poisoned to point at attacker-controlled domains (the repo builds such links — see `apps/accounts` activation flow).
- **Cache poisoning** if any intermediary caches per-Host.
- Django's own docs classify `ALLOWED_HOSTS` as a security control; `["*"]` disables it. Combined with `SECURE_PROXY_SSL_HEADER` trusting `X-Forwarded-Proto`, the app trusts client-supplied routing metadata end-to-end.

## How to reproduce

1. On a machine without `ALLOWED_HOSTS` exported, run `python -c "from config.settings.production import ALLOWED_HOSTS; print(ALLOWED_HOSTS)"` → prints `['*']`.
2. Or: `curl -H "Host: evil.example" https://fantasykenya.com/api/v1/profile/` — accepted instead of rejected with 400 Bad Request.

## Suggested fix

Three small changes, none of which can break local development:

1. **Pin production explicitly** — add to `config/settings/production.py`:

   ```python
   # base.py falls back to "*" when the env var is absent; production must
   # never inherit that fallback.
   ALLOWED_HOSTS = [
       h.strip()
       for h in re.split(r"[,\s]+", os.getenv("ALLOWED_HOSTS", ""), )
       if h.strip()
   ] or ["fantasykenya.com", "www.fantasykenya.com"]
   ```

   (or simpler: fail fast — `assert ALLOWED_HOSTS != ["*"], "Set ALLOWED_HOSTS in .env.prod"`).

2. **Document the variable** in `.env.example`:

   ```
   # Comma/space-separated hosts Django will serve. REQUIRED in production.
   ALLOWED_HOSTS=fantasykenya.com www.fantasykenya.com
   ```

3. **Add a regression test** asserting `config.settings.production.ALLOWED_HOSTS != ["*"]`, so the wildcard can never silently return.

## Applied fix

Not yet applied — this report documents the gap and the concrete patch. Item 1 is the load-bearing change; items 2–3 prevent recurrence.
